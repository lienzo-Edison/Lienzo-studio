# Lienzo Studio Technical SEO Audit

**Audit date:** July 17, 2026

**Primary domain:** `https://www.lienzo.studio`

**Framework:** Next.js 16 App Router

## Executive summary

The project already had a solid SEO foundation: descriptive route metadata, canonical tags on most commercial pages, a generated sitemap, Next.js image optimization, semantic headings, internal service/location links, and reusable Service/FAQ/Breadcrumb schema helpers.

The main technical risk was inconsistent hostname usage. Canonicals, structured data, the sitemap, robots file, and `llms.txt` used the apex domain even though the required primary domain is `www`. This can split signals if both hosts resolve. The implementation now uses one canonical hostname and permanently redirects the apex host.

Other completed improvements include full sitemap coverage, explicit indexing rules for non-search landing pages, complete Organization/LocalBusiness/Service schema relationships, a correct social preview image, enhanced manifest metadata, and keyboard skip navigation.

## Changes implemented

### XML sitemap

- Kept the sitemap as a typed Next.js metadata route at `/sitemap.xml`.
- Standardized every sitemap URL on `https://www.lienzo.studio`.
- Added all Mexico region pages, which were generated by the application but missing from the sitemap.
- Preserved published-only filtering for service pages.
- Removed request-time `lastModified: new Date()` values. A constantly changing timestamp suggests every URL changed on every sitemap request and gives crawlers a misleading freshness signal. Real modification dates should be added only when a content source can provide them.
- Kept `/privacy` out because it is explicitly non-indexable.

### Robots controls and page indexing

- Replaced the static `public/robots.txt` with a typed `app/robots.ts` metadata route.
- Published the canonical sitemap and preferred host in robots output.
- Continued blocking `/api/`.
- Added explicit global `index,follow` directives, including Google image/snippet/video preview settings.
- Added `noindex,follow` to `/privacy`; it remains accessible and its links can be followed without adding a low-value legal page to search results.

### Metadata and canonical URLs

- Centralized the preferred origin as `https://www.lienzo.studio` in `lib/schema.ts` and used it as `metadataBase`.
- Added a permanent host redirect from `lienzo.studio` to `www.lienzo.studio` while preserving paths.
- Updated hard-coded schema, sitemap, Open Graph, and `llms.txt` URLs to the preferred host.
- Retained route-specific canonical paths for all public commercial pages.
- Prevented duplicated brand suffixes on dynamic service, industry, and location titles by marking already-branded titles as absolute metadata values.
- Added application name, author, creator, publisher, and category metadata.
- Added page-specific titles, descriptions, canonicals, and indexing controls for the previously unconfigured Privacy route.

### Structured data

- Added a distinct `Organization` entity with a stable ID, logo, contact details, and social profiles.
- Retained a distinct `LocalBusiness`/`ProfessionalService` entity and linked it to the Organization as its parent.
- Connected all Service schema providers to the LocalBusiness entity by stable `@id`.
- Added a top-level `@graph` so Organization and LocalBusiness entities are emitted together without duplication.
- Added the branded social image to the LocalBusiness entity.
- Removed the unsupported `Mo-Su 00:00-23:59` opening-hours claim. Business hours should not be published unless they match real customer-facing hours.
- Added Breadcrumb schema to standard service pages, industry pages, and priority location pages. Niche service and About pages already had it.
- Reused the shared Service schema builder on industry and priority location pages to keep provider and area-served data consistent.

### Open Graph and Twitter Cards

- Replaced the square 512×512 favicon used as a `summary_large_image` with a dedicated 1200×630 branded social card.
- Added accurate width, height, and alt text.
- Kept inherited Open Graph and Twitter metadata so route-specific titles/descriptions combine with the global image and site identity.
- The generated asset is `public/og-image.png`.

### Favicon and web manifest

- Verified that 16×16 and 32×32 favicon PNGs, Apple touch icon, and 192×192/512×512 app icons exist and are referenced.
- Expanded the web manifest with a description, start URL, scope, language, categories, and brand-aligned theme/background colors.

### Breadcrumbs and internal linking

- Verified that primary pages have a clear back/up link and that commercial pages are reachable through the header, homepage/service modules, location/industry hubs, or footer.
- Added missing machine-readable breadcrumbs to dynamic commercial page families.
- Retained the footer links to Services, Industries, Locations, About, and the priority Bilingual Marketing page.

### Image optimization

- Verified that primary content and portfolio imagery uses `next/image`, responsive `sizes`, descriptive alt text, and selective priority loading.
- Kept the tracking pixel as a plain image because it is a 1×1 analytics fallback, not page content.
- Verified the new social image at exactly 1200×630.

### Performance affecting SEO

- Local fonts already use `next/font/local` with `display: swap`, reducing layout shift and avoiding third-party font requests.
- Images already use Next.js optimization and explicit dimensions/fill containers.
- Converted eight opaque portfolio PNGs to visually high-quality WebP at quality 90, while retaining two small PNGs where conversion would have increased file size.
- Resized oversized profile photos to a still-retina-ready 720×720 and reduced the current social card losslessly enough to preserve its typography.
- Resized and recompressed the unused 28 MB plant-shop source image to remove unnecessary deployment weight without affecting any live page.
- Added `npm run optimize:images` as a guarded, repeatable workflow for these assets. It skips already-optimized files and only replaces a candidate when it saves at least 10%.
- The optimization pass reduced the processed source assets from approximately 40.4 MB to 5.6 MB, an 86% reduction. Next.js continues generating responsive device-sized variants at request/build time.
- Removed false sitemap freshness timestamps, reducing unnecessary recrawl signals.
- The production build compiles and generates all static/dynamic route entries successfully.
- Google Analytics and Meta Pixel remain `afterInteractive`; they do not block initial HTML rendering.

### Accessibility affecting SEO

- Added a keyboard-visible “Skip to main content” link.
- Added a stable focus target around the main page content.
- Verified one primary `<h1>` on the main page templates reviewed and logical use of `<main>`, `<section>`, `<article>`, lists, and navigation landmarks.
- Verified meaningful alt text on content images and empty alt text on decorative imagery.
- Existing navigation controls include accessible labels and state attributes.

## Validation

- `npm run build`: **passed** with all 56 route entries generated.
- `git diff --check`: **passed**.
- Social image dimensions: **1200×630**.
- `npm run lint`: blocked by one pre-existing `react-hooks/set-state-in-effect` error in `components/PageTransitionProvider.tsx`. The audited SEO changes did not introduce this error; the production build and TypeScript checks pass.

## Additional recommendations requiring manual content or business input

1. **Confirm real business details for LocalBusiness schema.** Add a public street address, geo coordinates, price range, and actual opening hours only if they are accurate, customer-facing, and consistent with the Google Business Profile.
2. **Confirm the Google profile URL.** Replace the current `share.google` URL with the durable Google Business Profile/Maps URL if one is available.
3. **Create unique social cards for priority pages.** The global card is safe and complete; custom cards for flagship services, industries, and case studies could improve click-through rates.
4. **Add content-owned modification dates.** Connect sitemap `lastModified` values to CMS, Git, or a maintained content date rather than using the current request time.
5. **Strengthen portfolio case-study content.** Give each major project an indexable route with client-approved challenge, approach, deliverables, results, testimonial, and unique images. The current modal presentation limits organic landing-page potential.
6. **Add proof and original expertise.** Publish client-approved metrics, case studies, author bios, process details, and original research. These are content/E-E-A-T improvements rather than technical tags.
7. **Review localized URL strategy.** The interface changes language client-side while URLs and server metadata remain English-first. If Spanish organic growth is a priority, create durable Spanish URLs (for example `/es/...`) with translated server-rendered metadata, self-canonicals, and reciprocal `hreflang` annotations.
8. **Validate schema externally after deployment.** Test representative URLs in Google Rich Results Test and Schema.org Validator, then compare rendered values with the live Google Business Profile.
9. **Register both host variants in Search Console.** Use a Domain property, submit the `www` sitemap, monitor canonical selection and indexing, and retire any legacy apex sitemap submission after the redirect is live.
10. **Measure Core Web Vitals with field data.** Use Search Console and CrUX after deployment. Consider consent-aware loading for analytics/pixels and reduce motion/Three.js work if LCP, INP, or mobile battery usage is poor.
11. **Resolve the existing transition lint finding.** Refactor the route-transition state update in `PageTransitionProvider.tsx` so the full lint suite passes without suppressing the rule.
12. **Review page titles and descriptions in Search Console.** Adjust content based on real queries and CTR; avoid adding more keyword meta tags, which major search engines do not use for ranking.

## Deployment note

The host redirect requires the production platform to pass the original `Host` header through Next.js. After deployment, verify that `https://lienzo.studio/any-path` returns one permanent redirect directly to `https://www.lienzo.studio/any-path` with no redirect chain.
